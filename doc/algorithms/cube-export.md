# Cube Export And Import

## Purpose

Define MVP1 `.cube` export and import behavior so generated Film Rolls can be reused in compatible tools and existing local `.cube` LUTs can become Film Rolls.

## Inputs

- Stored 33x33x33 LUT RGB values for export.
- UTF-8 `.cube` text data for import.
- Film Roll name for export title and filename.
- Algorithm metadata.

## Output

- Text `.cube` file written or shared through the user-selected export flow.
- Parsed `LUT3D` model when the user creates a Film Roll from a `.cube` file.

## Required Header

MVP1 exports should include:

```text
TITLE "Film Roll Name"
LUT_3D_SIZE 33
DOMAIN_MIN 0.000000 0.000000 0.000000
DOMAIN_MAX 1.000000 1.000000 1.000000
```

Comments may include app name and algorithm version, but exported files should remain simple and broadly compatible.

## Value Ordering

The export order must match the stored LUT ordering and be documented in implementation tests.

Recommended MVP1 order:

```text
for blueIndex in 0..<size
  for greenIndex in 0..<size
    for redIndex in 0..<size
      write red green blue
```

Each index maps to `index / (size - 1)` in the identity domain. This red-fastest ordering is common for `.cube` 3D LUT files, but compatibility tests should verify import behavior in target tools where possible.

## Precision

- Write decimal values in `[0, 1]`.
- Use fixed precision, recommended six decimal places.
- Ensure exported values are finite and clamped before writing.
- Use newline-separated RGB triplets with spaces between values.

## Validation

Before export:

- Confirm LUT size is `33`.
- Confirm sample count is `35937`.
- Confirm all RGB values are finite.
- Confirm all values are within `[0, 1]` after clamp.
- Confirm title text is escaped or sanitized for `.cube` syntax.

After export:

- Re-parse fixture exports in tests.
- Confirm header fields are present.
- Confirm data line count equals `33 * 33 * 33`.
- Confirm first and last values match expected identity-domain corners after transform.

## Error States

- LUT data missing or corrupt.
- Imported `.cube` text is not UTF-8.
- Imported `.cube` file is missing `LUT_3D_SIZE`.
- Imported `.cube` row count does not equal `size * size * size`.
- Imported `.cube` contains unsupported 1D LUT data or RGB values outside `[0, 1]`.
- Film Roll name cannot be safely represented in `TITLE`.
- Export destination is unavailable.
- File write fails or is cancelled by the user.

## Data Dependencies

- Stored LUT values generated by the LUT generation module.
- Product/UX export flow.
- Architecture file-export service.

## Future Extension Points

- Alternate LUT sizes.
- Export comments with richer metadata.
- Optional 1D shaper LUTs outside MVP1.
- Wider domain values for HDR/Log workflows outside MVP1.

## Import Behavior

`CubeLUTImporter` parses simple UTF-8 3D `.cube` files locally. It accepts comments, `TITLE`, `LUT_3D_SIZE`, `DOMAIN_MIN`, `DOMAIN_MAX`, and RGB data rows in red-fastest order. It rejects 1D LUT declarations, malformed headers, unsupported lines, invalid row counts, non-finite values, and values outside `[0, 1]`.

Imported LUTs use algorithm version `mvp1.imported-cube.v1`. They bypass reference image analysis and LUT generation because the LUT is already user-provided. `CubeLUTPreviewRenderer` creates a local sRGB PNG gradient preview sampled through the imported LUT; `CreateFilmRollUseCase` stores that PNG as the Film Roll reference original and then creates the normal reference thumbnail. This keeps imported LUT rolls compatible with the existing MVP1 data model, which requires exactly one reference asset per Film Roll.

## Documentation Updates Completed

This document records `.cube` header requirements, value ordering, precision, validation, and compatibility risks.

Task 4 implementation records:

- `CubeExporter` serializes to `String` only; file writes are reserved for export-flow integration.
- Header lines are `TITLE`, `LUT_3D_SIZE`, `DOMAIN_MIN`, and `DOMAIN_MAX`.
- RGB data rows are written in stored red-fastest order with six-decimal fixed formatting.
- Double quotes in titles are escaped for `.cube` `TITLE` syntax; newlines are flattened to spaces.

Task 10 implementation records:

- `CubeLUTImporter` parses `.cube` text into `LUT3D` and reports recoverable `invalidCubeLUT` errors.
- `CubeLUTPreviewRenderer` generates a local PNG preview for imported LUT rolls.
- Create Film Roll Files import accepts `.cube` files alongside supported still images.
