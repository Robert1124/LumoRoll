# Photo Preview Rendering Service

## Purpose

Render temporary Apply-screen preview images for the current Film Roll, selected target photo, and intensity after the user imports a target photo.

## Inputs

- Film Roll ID.
- Preview render ID generated by the app.
- App-owned target photo path.
- Film Roll LUT.
- Intensity value from `0...100`.
- Preview maximum pixel dimension.

## Outputs

- App-owned relative path to a rendered preview JPEG.
- Echoed intensity for stale-result checks.
- Cleanup hook for discarded preview outputs.

## Data Dependencies

- The selected target photo must already be staged or stored inside the app container.
- The LUT comes from the selected Film Roll and must not be regenerated when intensity changes.
- Preview files live under temporary app storage and must never be appended to the Film Roll manifest.

## Relationship To Other Modules

- Domain owns the preview render request/result types and use case.
- Processing owns the Core Image preview renderer.
- Features own preview state and stale-result handling when preview UI is active.
- App wires the concrete renderer into `ApplyPhotoFeatureModel`; the Apply screen requests preview renders when the selected target or intensity changes.
- `PhotoDisplayImageStore` displays the rendered preview path just like other app-owned images.

## State Management

The Apply feature model owns preview state separately from save state:

- `idle`: no target photo is available.
- `rendering(previousPath)`: a preview render is in flight; the prior accepted preview can remain visible.
- `ready(path)`: the rendered preview is available for `After` and the right side of `Split`.
- `failed(message, previousPath)`: rendering failed; the user can still save or retry by changing the target/intensity.

When preview UI is active, selecting a new target clears stale preview state. Intensity changes schedule a new preview render but never mutate the Film Roll LUT. Duplicate or stale preview completions must be discarded so an old render cannot replace the current target or intensity.

## Error States

- Target path missing or unreadable.
- Film Roll missing.
- Core Image render failure.
- Preview file write failure.
- Stale render completion after target or intensity changes.

Failures should keep the original target available for retry. The current import-first Apply flow still saves through the final Film Roll render path and does not show Save to Photos.

## Empty States

Before a target photo is selected, the Apply screen shows only the centered import target panel and no preview render is requested. After target selection, the selected-target editor shows Before/Split/After preview and uses temporary preview renders until the user taps `Save` or `Cancel`.

## Future Extension Points

- Debounced preview rendering during slider drag.
- Reusing an already rendered preview for Save to Photos when intensity and source match.
- Preview cache eviction policy.
- Lower-resolution preview on memory-constrained devices.
